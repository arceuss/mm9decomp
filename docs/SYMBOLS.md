# Symbols

`config/WR9E/symbols.txt` was generated by decomp-toolkit's analysis of the DOL (no map file exists for this game). Names are address based:

- `fn_XXXXXXXX`: function found by control-flow analysis.
- `lbl_XXXXXXXX`: data object; size and `data:` type were guessed by dtk from accesses and may be wrong.
- `jumptable_XXXXXXXX`: switch jump table.
- Real names exist only for library code dtk recognises by signature (RVL SDK OS/EXI/SI/DVD/GX/IPC/NAND/SC/ES, MetroTRK, MSL, PPCEABI runtime), e.g. `OSInit`, `memcpy`, `__init_cpp_exceptions`. 444 more functions are bounded by exception tables.

8283 functions total; 2941 lie in the game range 0x8000BF80..0x800EB1CC.

The IDA database (`game/base/mm9-game.dol.i64`) is plain auto-analysis: 7358 functions, one name (`start`), no types, no comments. It was used for xrefs and string references only, from a copy in `build/ida/` so the original stays untouched.

## Naming policy

Don't rename to semantic names without evidence (strings, SDK signatures, unambiguous use). Struct types and fields use `Unk<ADDR>` / `unkXX` until their purpose is pinned down. Shared partial structs live in `include/game/`:

- `obj.h`: pooled object from `fn_800E8C44(lbl_804EE738)`, initialised by `fn_80042DA0(obj, type)`.
- `stateobj.h`: object with `state` at 0x11 and `flags14` at 0x14 used by the per-type update/draw pairs.
- `work_802BDCC0.h`: the big work area at the start of `.bss`.
